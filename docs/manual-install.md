# 手动搭建说明

想自己一步步建，或者让 AI 帮你装时卡住了，用这份说明。

## 照着搭的三步

刚起步，先按「单个/相似任务＝一个机器人」跑通。下面三步，是进阶之后搭完整组织时用的。

1. **先搭框架，不急着干活。** 先建一个入口机器人，再把各角色建出来。每个角色的说明先写清：定位、职责、不做什么、交给谁、什么时候停下来问人、向谁汇报。建的时候一次带上完整说明。
2. **往岗位里塞工作流。** 把手上已经打磨过的 Skill 按岗位分进去，不要一个 Skill 建一个机器人。再把几条链写进入口机器人的说明里，让它知道谁先谁后、交给谁。
3. **跑起来，每周复盘再优化。** 从一条最常用的链开始跑，每周让复盘机器人收经验、写周报。哪里分工打架、哪个角色空转、哪条边界没写清，就由入口机器人提出改法，你拍板后再改说明或 Skill。

## 每个机器人的说明里贴什么

每份岗位说明都从「定位」开始贴，一次带上完整说明。

| 机器人 | 说明里贴什么 |
|---|---|
| 出海船长 | [roles/00-captain.md](../roles/00-captain.md) + README 的[四条链加一个回路](../README.md#四条链加一个回路) + [全员通用规则](../common-rules.md) |
| 岗位 1 到岗位 12 | `roles/` 里对应的岗位说明 + [全员通用规则](../common-rules.md) |

## 改成你自己的

- 岗位按功能拆，先看哪些工作值得单独有人负责，不用照搬我这 12 个岗位。
- 给机器人起名字，主要是方便自己认、方便派活；名字定了，能力边界也要单独写。
- 删掉或改名某个岗位时，把其他岗位「交给谁」、四条链和全员通用规则里提到它的地方一起改（管合规的守门员、抓运营复盘的机器人分别在通用规则第 6、7 条里被点名）。
- 所有机器人共用一台云电脑，岗位说明里写的边界只是约定，不等于技术上隔开了。要人最后把关的地方，写进交接关系里，别只写在总提示词里。
